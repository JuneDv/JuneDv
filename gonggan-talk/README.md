# 공간 Talk — 건축주 소통 · 현장 운영 프로그램

모듈러 주택 회사의 현장 운영 도구. **현장마다 따로 만들던 구글 시트 공정현황과 카카오톡 단톡방을 앱 하나로 통합**했습니다.
2026년 10월 기준 진행 중 현장 719개, 세부공정 10,633건을 Jira에서 4시간마다 자동 반영해 운영 중입니다.

- 건축주 앱: https://bm-status-app.vercel.app (안드로이드 앱 "공간 Talk")
- 관리자 앱: 사내 전용
- 코드: 비공개 (문의 시 열람 가능)

## 1. 문제

| 기존 | 문제 |
|---|---|
| 구글 시트 "업무흐름 현황" — 건축주에게 보여 주려고 현장마다 수작업 생성 | 담당자가 공종별 체크리스트를 손으로 갱신. Jira 상태와 별도 관리 → 불일치. 생산 출고 시트(39칸)도 동일 |
| 카카오톡 단톡방 — 현장마다 신규 생성 | 기록이 담당자 개인 계정에 잔류 → 담당자 교체 시 단절, 이력 검색 곤란 |
| "지금 어디까지 됐어요?" 전화 문의 | 담당자가 매번 Jira를 열어 찾아서 회신 |

세 가지 모두 사람이 중간에서 옮겨 적거나 찾아서 답하던 일입니다.

## 2. 구성

| 부분 | 대체 대상 | 내용 |
|---|---|---|
| **건축주 앱 (공간 Talk)** | 단톡방 | 휴대폰 번호 + 계약번호 접속. 8단계 진행·공정률, 단계별 "하실 일"·납부 상태, 담당자 대화·전화, 푸시 알림. 가족도 같은 번호로 접속 |
| **관리자 앱** | 시트 | 현장 목록·상세, 건축주 채널 + 내부 채널, 서류함, 시트를 대체하는 생산 출고 관리(칸 클릭 입력, 경고 표시, Ctrl+Z) |
| **자동 동기화** | 옮겨 적기 | n8n이 Jira 현장 정보·세부공정을 4시간마다 앱 DB(Supabase)로 이관. 앱 입력값은 Jira를 바꾸지 않음 |

## 3. 구조

![전체 구조](docs/structure.png)

파란 선은 현장 데이터의 길(Jira → n8n → DB), 주황 선은 알림의 길(DB → 알림 함수 → 휴대폰).
두 앱은 DB를 직접 읽고 쓰되, 권한 규칙(RLS)으로 건축주는 본인 현장만, 직원은 허용된 현장만 받습니다.

## 5. 데이터와 권한

- **원본은 Jira.** 상태 변경은 Jira에서만. 앱에서 적은 값(상차일·인허가·기초·메모·대화)은 앱 DB에만 저장하고 Jira로 되쓰지 않음. 둘이 다르면 "수정됨" 표시만
- **동기화 범위를 벗어난 행은 자동 정리** (fresh 행이 있을 때만 삭제)
- **권한은 화면이 아니라 DB(RLS)·서버 함수에서 확인.** 담당자는 자기 현장·대화만, 공무·PM·관리자·운영자는 전체와 생산 출고 수정, 운영자만 가입 승인·역할 지정
- 건축주 로그인은 서버 함수(1시간 5회 실패 시 차단), 비밀번호는 해시 저장, 비밀 키는 Vault
- 생산 출고 입력마다 누가 언제 고쳤는지 기록. 보관 기간 지난 기록은 매일 새벽 자동 삭제

## 6. 기술

| | |
|---|---|
| 프런트 | 바닐라 JS PWA(의존성 0), Android TWA, Vercel |
| 백엔드 | Supabase: Postgres + RLS, Edge Functions(로그인·푸시·정리), Realtime, Storage, Vault |
| 연동 | n8n(4시간 주기 Jira → DB), Jira REST API, Google Sheets 이관 스크립트 |
| 알림 | 웹 푸시(FCM/APNs), 근무시간·조용한 시간 규칙 |
| 품질 | Playwright 시각 회귀 테스트(가짜 Supabase 스텁), 적대적 멀티모델 리뷰([iris](https://github.com/JuneDv/iris)) |

## 7. 내가 한 일

- 문제 정의와 범위: 시트·단톡방·Jira를 어떻게 하나로 묶을지, 무엇을 Jira에 두고 무엇을 앱에 둘지 결정
- 데이터 설계: 현장·세부공정·대화·생산 출고 테이블, 권한 규칙, 동기화 정리 규칙
- Jira·n8n 연동 설계와 운영, 시트 데이터 이관
- 화면 설계와 검수: 건축주 앱 8단계 판정 규칙, 관리자 앱 생산 출고 탭의 시트 호환 구조
- 구현은 Claude Code와 짝 개발. 설계·검수·배포 판단은 직접 [비율이나 역할 보완]
